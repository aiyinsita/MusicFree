# MODIS 海表净辐射反演框架

基于 MODIS TOA 数据，利用 **Set-Attention 日内观测编码器 + LSTM + Transformer** 时序模型进行海表净辐射（W/m²）反演。

## 1. 问题背景与设计决策

| 问题 | 答案 |
|------|------|
| 编码器方案（将一天的多次观测压缩为一个向量）是否合适？ | **是，且推荐使用 Set-Attention 编码器**（见第 3 节） |
| MYD 夜间数据是否应纳入模型？ | **应该纳入**，并通过波段掩码 + 缺失波段嵌入处理缺失的可见光波段（见第 4 节） |

## 2. 模型架构

```
输入：每个网格点，每天
  ┌──────────────────────────────────────────────────────────────┐
  │  MODIS 观测序列（当天 N 次过境，N 不固定）                     │
  │  每次观测包含 36 个波段的 TOA 反射率 / 亮温                   │
  └──────────────────────────────────────────────────────────────┘
            │
            ▼
  ┌──────────────────────────────────┐
  │  DailyObservationEncoder         │  ← observation_encoder.py
  │  (Set-Attention / Cross-Attention)│
  │  输出：每天一个固定维度嵌入向量   │
  └──────────────────────────────────┘
            │  (W 天的嵌入序列)
            ▼
  ┌──────────────────────────────────┐
  │  Bidirectional LSTM              │  ← model.py
  │  (捕获局部时序依赖关系)           │
  └──────────────────────────────────┘
            │
            ▼
  ┌──────────────────────────────────┐
  │  Sinusoidal Positional Encoding  │
  │  + Causal Transformer Encoder    │  (因果掩码，防止未来信息泄漏)
  └──────────────────────────────────┘
            │
            ▼
  ┌──────────────────────────────────┐
  │  MLP Regression Head             │
  │  输出：每天的净辐射预测 (W/m²)   │
  └──────────────────────────────────┘
```

### 设计要点

- **双向 LSTM**：在窗口内双向捕获短期时序上下文（云覆盖变化、天气系统移动）。
- **因果 Transformer**：对更长时程依赖建模，同时因果掩码保证预测只依赖当前及历史信息，适用于业务化部署。
- **窗口长度 W**：推荐 W = 5 天。5 天窗口能覆盖一次典型的天气系统过境周期，同时保持标签延迟较低。W = 3 也可行，适合要求更低延迟的场景。

## 3. 日内多次观测的编码方案

### 3.1 问题描述

MODIS（Terra/Aqua）每天对同一位置有 0～6 次有效晴空观测，且不同位置的观测次数不同，无法直接用固定长度的输入张量表示。

### 3.2 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 简单均值/最大值池化 | 实现简单 | 丢失角度多样性和时间采样信息 |
| RNN（逐次观测输入） | 能捕获序列关系 | 假设观测有时间顺序（实际上意义不大）；难以批处理可变长度 |
| **Set-Attention 编码器（本方案）** | 置换不变；能处理变长输入；可学习的注意力权重 | 计算量略高于池化，但仍很轻量 |

### 3.3 Set-Attention 编码器工作原理

```
观测向量 o_1, o_2, ..., o_N  (N 不固定)
    │
    ▼  Linear projection
x_1, x_2, ..., x_N  ∈ ℝ^hidden_dim
    │
    ▼  + 缺失波段修正（见第 4 节）
    │
    ▼  Cross-Attention
        Query: K 个可学习的 Latent 向量 (K << N，默认 K=4)
        Key/Value: x_1...x_N
    │
    ▼  Feed-Forward 精化
    │
    ▼  展平 + Linear 投影
每日嵌入向量 ∈ ℝ^embed_dim
```

**核心思想**：用少量"潜变量"（Latent queries）通过 Cross-Attention 聚合所有观测的信息，天然支持可变长度输入，且对观测排列顺序不敏感。

### 3.4 批处理技巧

训练时将同一天内的不同观测填充到统一长度（`max_obs_per_day`），填充位置用 `obs_padding_mask` 标记为 True，在 Cross-Attention 的 `key_padding_mask` 中忽略这些位置。

## 4. MYD（Aqua）夜间数据与可见光波段缺失处理

### 4.1 是否应该使用 MYD 夜间数据？

**结论：应该使用。**

理由：
- MODIS 热红外波段（Bands 20-36）在夜间仍可正常观测，包含地表温度、大气水汽、云检测等辐射收支相关信息。
- 夜间净辐射中的长波分量（向上/向下长波辐射）可以从热红外信息中估算。
- 增加夜间观测可以显著增加每日的有效观测次数，尤其对高纬度地区（夜间时间长）效果明显。

### 4.2 可见光波段缺失的处理方案

本框架采用 **"波段掩码 + 缺失波段嵌入"** 方案：

```python
# 夜间观测的可见光波段（Bands 1-7，索引 0-6）标记为缺失
band_mask[night_obs_slot, :7] = True
obs[band_mask] = 0.0  # 缺失位置填 0

# 编码器内部：
correction = einsum("btn,nh->bth", band_mask.float(), missing_band_embed)
x = input_proj(obs) + correction
```

- `missing_band_embed`：可学习的参数矩阵，形状 `(num_bands, hidden_dim)`。
- 对于每个缺失波段，将对应的可学习向量**加到**投影特征上。
- 这使模型能够区分"波段存在但值为零"与"波段缺失"两种情况。

### 4.3 替代方案

| 方案 | 说明 |
|------|------|
| 仅使用白天观测 | 简单，但浪费数据，夜间信息丢失 |
| 为日间/夜间分别训练独立模型 | 模型数量翻倍，维护成本高 |
| 使用 NaN 填充 + 缺失值感知的注意力 | 与本方案类似，但实现更复杂 |
| **波段掩码 + 可学习缺失嵌入（本方案）** | 统一处理，可学习如何利用部分信息 |

## 5. 数据集划分

### 5.1 划分原则

海表辐射具有强烈的年际变化（ENSO、PDO 等），必须按**时间顺序**划分，不能随机打乱，否则：
- 验证集中的信息会泄漏到训练集（未来数据参与了模型训练）。
- 验证/测试指标会虚高，模型在实际部署中表现差。

### 5.2 推荐划分方案

假设使用 2003–2022 年共 20 年的 MOD + MYD 数据（MODIS Terra 2000 年发射，但 2002 年前数据质量较差）：

```
┌─────────────┬──────────────────────────────────────────┬──────┐
│  数据集      │  年份（含）                               │  比例 │
├─────────────┼──────────────────────────────────────────┼──────┤
│  训练集      │  2003–2016  (14 年)                      │  ~70% │
│  验证集      │  2017–2018  ( 2 年)                      │  ~10% │
│  测试集      │  2019–2022  ( 4 年)                      │  ~20% │
└─────────────┴──────────────────────────────────────────┴──────┘
```

**选择理由**：
- 训练集包含足够多的年份，覆盖多个 ENSO 循环（~3–5 年一个周期）。
- 验证集（2017–2018）位于训练集之后，用于超参数调整和早停，不参与测试评估。
- 测试集（2019–2022）包含 2019–2020 年的印度洋偶极子强事件和 COVID-19 期间的大气环境变化，具有代表性和挑战性。
- 测试集数据**完全不接触训练过程**，所有归一化统计量只在训练集上计算。

### 5.3 若使用完整 Terra 记录（2000–2022）

```
训练集: 2000–2014  (15 年)
验证集: 2015–2016  ( 2 年)
测试集: 2017–2022  ( 6 年)
```

### 5.4 实测站点验证

实测站点（如浮标、船载辐射计等）数据**不应混入训练或验证集**，仅用于**独立验证**，作为最终模型精度的物理参考：

```
GLDAS/GHOSE  →  训练目标（大面积覆盖）
实测站点      →  独立物理验证（评估模型真实误差）
```

## 6. 快速开始

### 6.1 安装依赖

```bash
pip install -r modis_radiation/requirements.txt
```

### 6.2 数据预处理

在 `data_root` 目录下准备以下 NumPy 文件：

| 文件名 | 形状 | 说明 |
|--------|------|------|
| `obs_data.npy` | `(n_days, n_lat, n_lon, max_obs, 36)` | TOA 反射率/亮温，float32 |
| `obs_mask.npy` | `(n_days, n_lat, n_lon, max_obs)` | 填充位为 True，bool |
| `is_night.npy` | `(n_days, n_lat, n_lon, max_obs)` | 夜间观测位为 True，bool |
| `target.npy` | `(n_days, n_lat, n_lon)` | GLDAS 净辐射 W/m²，float32 |
| `day_index.npy` | `(n_days,)` | datetime64[D]，如 `2003-01-01` |
| `aux.npy` | `(n_days, n_lat, n_lon, n_aux)` | 辅助特征（可选） |

### 6.3 训练

```bash
python -m modis_radiation.train \
    --data_root /path/to/data \
    --window 5 \
    --epochs 100 \
    --batch_size 32 \
    --lr 1e-4 \
    --output_dir ./checkpoints
```

### 6.4 运行测试

```bash
pytest tests/test_modis_radiation.py -v
```
